# Implementation Plan: יועץ הרכב של שטראוס

## Overview

תוכנית מימוש מדורגת (שלבים 0–9) הנגזרת מ-`requirements.md` (מזוהה `REQ-*` / `AC-*`) ומ-`design.md` (סעיפים §1–§10, Correctness Properties, Error Handling, Testing Strategy). כל משימה היא צעד קוד מוחשי המפנה למזהי הדרישות ולסעיפי העיצוב שהיא מממשת, ומציינת מה נבדק. סדר העבודה: תחילה עבודה לא-חסומה (שלב 0 שלד + שלב 2 מנוע/יבוא), שלב 1 (היתכנות) רץ במקביל ברגע שהשלד קיים.

**החלטות גרסת כללים (מחייב):** `calculateScenario` מקבל כפרמטרים מפורשים של rule-set מתוך ה-JSON: `contributionsBase`, `pensionCredit {rate, maxContributionRate, incomeCeiling}`, `rounding {during, display}`, `participation {treatment, reducesValueOfUse}`, `familyTrack {cars, priceSource, gapSplitEmployee}`. גרסאות rule-set מובחנות לפי **content hash** ולא לפי מחרוזת `version` (§2.1). שני קבצי הכללים (ישן + מעודכן) ניתנים לייבוא.

**החלטות פתוחות:** משימות התלויות ב-O1, O4, O5, O8, O9, O10, O11, O12, O13 מסומנות בהערה "⚠️ החלטה פתוחה" — ההתנהגות הבטוחה המתועדת (נספח א' / §10) חלה עד להכרעה, כך שאינן חסומות.

שפה: TypeScript על Next.js App Router (§1, §2). PBT: `fast-check`. בדיקות: Vitest + Playwright (§12 / Testing Strategy).
